## Impact

- Production: none (identical app code either side of the rollback; functions.php untouched; 0 5xx).
- Loop: 09-22 run success = 0 (no digest, no daily PR, 2 merges, 0 ledger rows on `main`). Third run killed at the ceiling in five days (09-18, 09-19, 09-22).
- Ledger: #147 and #142 had no row on `main` until 2026-09-23 (rows landed by Ops via `ledger-commit.sh`).

## Root causes

1. **Runner (class):** `claude -p` terminates background tasks 600 s after the main turn ends. Quinn's turn ends once the agents are dispatched, so every agent that needs > 10 min (build + type-check + PR + merge-gate + a 6–10 min deploy-verify) is killed mid-flight. Fix: PR E91 sets `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` in `run-funnel-daily.sh` (default 2 h, `FUNNEL_BG_WAIT_CEILING_MS` overrides) and a unit test asserts it stays set.
2. **deploy-verify (false-alarm class):** an empty `check-blog-sidebar` result was graded FAIL; CLAUDE.md: "Could not run ≠ is broken". Fix: empty output → INCONCLUSIVE (exit 0, no rollback, row says so); `check-blog-sidebar.sh` now prints `[WARN] could not fetch` and exits 2 on a curl failure instead of dying silently.
3. **smoke-render (false-alarm class):** a single navigation timeout on a secondary URL (sitemap, llms.txt, feeds) was a structural failure with no retry. Fix: secondary-kind navigation failures are re-rendered once with a fresh page; they fail only if they reproduce.

## Still open (queued as `[ops]` ideas, not built here)

- `deploy-verify.sh` picks `smoke-render.ts` from whichever tree has `node_modules/playwright` first — the operator tree's stale copy (7 targets) ran on 09-22 even though the agent worktree had playwright installed. It should run `$ROOT`'s script with `NODE_PATH` from the deps tree.
- The runner's `cleanup` trap deletes agent worktrees while their child processes may still be running; with the ceiling fixed this cannot recur from the kill path, but a `pkill -f "$WT-"` or a wait-for-children before `git worktree remove` would make it impossible.
- Runner step 1b treats any non-zero `check-blog-sidebar` exit as "markers missing" and re-pushes functions.php on a red-health day; it should act only on exit 1.
